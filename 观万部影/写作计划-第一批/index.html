    观万部影 · 第一批写作计划（29 部）¶

    目标：把第一批 29 部按七段式写完，并确立后续 96 部的可复制流程。 模式：多 agent 并行写作 + 主 agent 总控。

    一、先认一条风险¶

    本项目历史上并行 agent 反复失败：

    • API Error: 502 请求转发失败
    • Stream error: error decoding response body
    • subagent_tokens: 0，文件根本没写出来

    所以本计划的原则是：每个 agent 只写一个文件；每批写完立刻校验；失败的那一篇由主 agent 直接接手补写。 不做"一个大 agent 包干五部"，因为那样失败一次就损失五部。

    二、分工¶

    角色 负责
    主 agent（总控） 定标准、写标杆篇、派活、逐批判收、修错、更新 README、提交
    写作 agent 每次只写 1 部，输出 1 个文件，不碰其他文件

    三、推进节奏（四步）¶

    第 0 步：标杆篇（1 部）¶

    《活着》（家庭-04）由谁写，见下方待定项。

    标杆篇的作用不是"多一篇"，是给出可复制的实物标准：七段怎么写、"呼吸感"是什么密度、金句长什么样。后续 agent 会拿到它当参照。

    第 1 步：试点批（2 部）¶

    派 2 个 agent 并行，写：

    • 《花样年华》（爱与关系-02）——验证"04 为什么伟大"里的影像语言
    • 《寄生虫》（社会与阶级-01）——验证"05 人类问题"的社会层

    为什么只 2 部：先确认并发在当前环境下能不能跑通、跑出来的质量是否稳定。跑通再放大。

    第 2 步：批量推进（剩余 26 部）¶

    按主题成组，每批 4 部（8 个主题分 7 批推完）。

    同一主题的片子放在同一批，好处是 agent 之间可以共享同一套"主题级判断"，风格更一致。

    第 3 步：收尾¶

    • 全批校验
    • 更新 README.md 进度表
    • 提交推送

    四、每个 agent 的输入规格（统一发给它）¶

    你要为《某片》（年份，国家，导演）写一篇 2500–6000 字（按分层）的观影深解。

【结构】严格七段，标题逐字一致：
01 电影名片（约200字）      年份/国家/导演/主演/类型/时代背景 + 一句话：它为什么值得看
02 故事（800–1500字）       开端→冲突→转折→高潮→结局；允许剧透；保留改变人物命运的细节
03 关键人物 + 关键场景（500–800字）  3–6 人 / 3–5 场，每场只答"发生了什么、为什么重要"
04 为什么它伟大？（500–1000字）  导演手法/表演/摄影/剪辑/音乐/叙事结构；每个技术点都要服务于"这部片为什么特别"
05 进入人类问题（800–1200字）   1–3 个核心问题；每问三层：电影给了什么答案 / 这个答案的局限 / 我们今天怎么看
06 认知连接（300–500字）     接进体系（主题→相关书→理论→现实），末尾留 3 个值得思考的问题
07 一句话记住（约50字）      收尾金句

【风格】短句、单行成段、段落最多 3–4 行、每篇 2–4 处加粗金句、不堆概念。

【纪律】
- 事实必须准确：年份、导演、演员、情节、台词都不能编。
- 不确定的细节宁可不写，绝不虚构。
- 敏感题材（战争、制度、历史）只解释机制，不做政治表态，不整体评判任何群体。
- 只创建/写入指定的那一个文件，不要改动其他文件。

【输出】写入 观万部影/films/<主题>-<序号>-<片名>.md

    五、验收标准（每篇必查）¶

    篇幅口径统一按「字符数（含标点）」计，与 wc -m 一致： 普通 2500–4000 · 核心经典 4000–5500 · 文明级 5500–8000。 （标杆《活着》实测 5733 字符，属文明级区间。）

    # 检查项 判定
    1 文件存在且非空 必须
    2 七个段落齐全（01–07） 必须
    3 篇幅落在分层区间内 必须
    4 无虚构事实（年份/导演/情节） 抽查
    5 段落不超 4 行、有加粗金句 抽查
    6 无政治表态、无群体整体评价 抽查

    六、失败处理¶

    情况 处理
    agent 报 502 / stream error 该篇由主 agent 直接写，不再重派同一片
    agent 写了但质量不达标 主 agent 就地重写，不返工给 agent
    文件路径错 / 改动了其他文件 主 agent 修正并记录

    • 全部七段齐全、层级标注与 125 部清单一致、引用编号全部有效
    • agent 失败（502 / stream error）共 2 次，其中 1 次文件仍成功落盘；失败件由主 agent 亲自补写
