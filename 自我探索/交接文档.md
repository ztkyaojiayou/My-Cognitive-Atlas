## 3. 每个问题的硬性结构（七段式）

标题用 `# 问题N：<问题>`，正文严格七段：

```markdown
# 问题N：XXXX？

## ① 为什么这个问题困扰我们？
从真实生活经验切入——具体场景、具体瞬间、具体的一句话。
不要抽象开场，要让读者"这就是我"。

## ② 它的本质是什么？
拆解困惑，区分易混概念，点出深层结构。
至少 1-2 句加粗的结构性判断。

## ③ 各学派怎么回答？
3 个立场左右，每个立场：

### <学派/人物>：<这一句要点>

<2-4 段展开，可以用《书名》引出人物观点>

> 经典：《书名》——→ 读万卷书/books/<真实文件名>.md

## ④ 常见的误区
**误区一：……** 一两句点破。
**误区二：……**
**误区三：……**
**误区四：……**

## ⑤ 中国处境
（★中国坐标问写"## ⑤ 中国处境 （里纵深）"，要明显更深）
写中国现实中的具体表现、成因、两代人的处境、时代结构。
只描述现象与机制，不做政治判断。

## ⑥ 如果是你，可以怎么想？
**一、……** 可操作的思考路径
**二、……**
**三、……**
**四、……**

## ⑦ 一句话记住

> **<一句能被带走的话>**
```

每个问题之间用一行 `---` 分隔。

## 4. 引用规范（最容易出事，务必照做）

### 格式（必须逐字符一致）

```
> 经典：《书名》——→ 读万卷书/books/<分类>-<编号>-<书名>.md
```

也允许：

```
> 参考：《书名》——→ 读万卷书/books/<分类>-<编号>-<书名>.md
```

### 硬性要求

1. 每个问题 **至少 1 条硬引用，目标 3 条**（对应 ③ 的每个学派块一条）。
   - 现有绝大多数问为 3 条；少量问只有 1-2 条（如 `23-概率与不确定性` 的 Q4=1、Q7=2、Q8=2），因为这些块谈的是通用概念（"大数定律""统计学描述"），正文没有对应到某一本具体的书。
   - **原则：不为凑数硬挂。** 引的书必须和这一段谈的人物/书对得上——宁可少一条，不可挂假书。
2. 引用位置：**放在每个 `### ` 学派块的末尾**，块尾空一行后即为引用行。
3. **书必须真实存在**。写之前先 `ls` 核对文件名，写之后跑第 10 节校验。
4. 同一问题可重复引同一本书（例如《乡土中国》在多问出现），不必刻意求新。

### 形式

- 每个 `### ` 块下面 2-4 段，段与段之间空一行；段内可以含书中的原话（用引号）。
- 加粗用在"结构性判断"和"金句"上，每问 2-4 处，不要满屏加粗。

## 5. 行文风格（用户最在意的点）

用户明确要求：**类似 ChatGPT 的、有"呼吸感"的行文**，不要教科书腔。

具体要求：

- **短句为主**。一句话能说完的，不要拧成两句。
- **单行成段**。大量段落只有 1 行，最多 3-4 行。
- 段落之间空行，制造停顿感。
- 用设问、短转折、口语词（"于是""可""说到底""你要问"）推进。
- **不要堆概念**。每个抽象词后面跟一个具体例子。
- **金句**：每问 2-4 处加粗，⑦ 的那一句最重。
- 篇幅：**每问 ≥120 行**（现有文件平均约 108 行，偏短的问题要多铺场景与纵深）。

反例（不要写）：
> 儒家思想强调伦理本位，主张通过道德修养实现个体与社会的统一。

正例（这样写）：
> 孔子把这件事讲得很具体——他不谈"人应该善良"，他谈：你对父母该怎样，对兄长该怎样。

## 6. 敏感话题：只解释机制，不表态

有些问题必然触及敏感区（历史与制度、社会现象、群体评价、传统与现代之争）。

**铁律：**

- **不站政治立场**，不做价值宣判，不评价任何群体整体。
- 只写 **现象 + 成因 + 机制 + 个体处境**。
- 用中性的"理解机制"笔法："它为什么会这样形成""它给个体带来什么"。
- 涉及当代议题时，写"结构怎么作用于人"，不写"谁对谁错"。

已处理过的敏感类问题（可作为笔法参照）：

- 第六卷"短快爽"内容为何成精神主食
- 第三卷"明规则与潜规则并存"
- 第四卷"人情、面子、关系"
- 第五卷"中医之辩""养生谣言""经验之谈"

这些问题的共同写法：**先说清它怎么运作，再说个体在其中有几种选择**，始终不下判决。

### 9.2 追加技法（每次追加都照做）

首次用 Write 写头部，**结尾留一行 `---`**。

之后每追加一段时间：

```bash
cd "/Users/zoutongkun/Desktop/认知体系构建/自我探索"

# 1) 删掉文件末尾的 ---（避免出现连续两条分隔线）
sed -i '' '$ d' "自我探索-XX-xxx.md"

# 2) 追加内容（结尾自带 ---）
cat >> "自我探索-XX-xxx.md" << 'PROBLEMS_END'

---

# 问题N：……

……

---
PROBLEMS_END

# 3) 检查 heredoc 标记是否有残留
grep -n 'PROBLEMS_END' "自我探索-XX-xxx.md"
```

> ⚠️ 平台差异：`sed -i ''` 是 **macOS（BSD）** 语法。**公司环境若是 Linux，要改成 `sed -i '$ d'`（无空字符串）。**
> ⚠️ heredoc 标记用 `PROBLEMS_END` 这类独特的词，不要用 `EOF`，正文里也不要出现该词。

### 9.3 补引用行（如果发现漏了）

**不要**用长文本当锚点匹配（引号、全角半角差异极易失败）。
正确做法：写个 Python 脚本，**按 `### ` 块结构定位**——找到每个 `### ` 标题，向后扫到下一个 `### ` 或 `## ④`，在块尾最后一个非空行后插入引用行。

参考实现（已在本项目验证可用）：

```python
# -*- coding: utf-8 -*-
import io

PATH = "/Users/zoutongkun/Desktop/认知体系构建/自我探索/自我探索-XX-xxx.md"

# heading 前缀 -> (显示书名, 真实文件名)
CITES = [
    (u'### 儒家（孔子）：仁者，人也', u'论语', u'宗教与精神世界-02-论语.md'),
    # ...
]

with io.open(PATH, 'r', encoding='utf-8') as f:
    lines = f.readlines()

block_ends = []
for head, title, filename in CITES:
    hi = next((i for i, l in enumerate(lines) if l.startswith(head)), None)
    if hi is None:
        print("NOT FOUND:", head); continue
    k = hi + 1
    while k < len(lines) and not lines[k].startswith(u'### ') and not lines[k].startswith(u'## ④'):
        k += 1
    t = k - 1
    while t >= hi and lines[t].strip() == '':
        t -= 1
    block_ends.append((t + 1, u'> 经典：《%s》——→ 读万卷书/books/%s\n' % (title, filename), head))

for idx, cite, head in sorted(block_ends, key=lambda x: -x[0]):
    lines.insert(idx, cite)
    print("INSERT:", head.strip())

with io.open(PATH, 'w', encoding='utf-8') as f:
    f.writelines(lines)
```

**推荐流程**：用 Write 工具单独写脚本文件，再用一条简短的 Bash 命令执行。
（把"写脚本 + 执行"塞进一条超长 bash 命令，容易被权限拒绝。）

## 10. 校验命令（每次写完必跑）

### 10.1 单文件校验

```bash
cd "/Users/zoutongkun/Desktop/认知体系构建"
f="自我探索/自我探索-28-中国认知坐标.md"

# 结构 + 引用行数量
echo "问题:$(grep -cE '^# 问题' "$f")  ⑦:$(grep -cE '^## ⑦ ' "$f")  引用行:$(grep -c '读万卷书/books' "$f")"

# 引用书目是否存在
grep -oE '读万卷书/books/[^ ]+\.md' "$f" | sort -u | while read p; do
  [ -f "$p" ] && echo "OK  $p" || echo "MISSING  $p"
done
```

**判定标准：**

- 问题数 == ⑦ 段数 ✅ 必须
- 没有任何 `MISSING` ✅ 必须
- 引用行数 ≥ 问题数（底线：每问至少 1 条）
- 引用行数达到 3 × 问题数为理想；落在 1-2 倍之间的，人工看一眼那几问的 ③ 是不是漏挂了

## 11. 已知坑与教训（都是真踩过的）

### 坑 1：引用行整段漏写（最高发、最严重）

**现象**：正文写得挺完整，但 `③` 的每个学派块后面**根本没有** `> 经典：` 行。跑校验时引用行为 0。

**已经发生过三次**：

1. 第六卷文学卷（Q1-12 全部漏写）
2. 贯穿轴中国认知坐标卷（Q1-8 全部漏写，写完 Q9-12 才发现）
3. 第五卷概率卷 `23-概率与不确定性`（Q9-Q12 全部漏写，2026-11-07 交接时才发现，已补齐 12 条）

**原因**：一次性写太多、注意力全在内容上，忘了每块都要挂引用。

**教训**：每次收尾都必须跑第 10.2 节的全模块体检——这是唯一能可靠发现该类问题的办法，靠肉眼通读会漏。

**防御**：
- 写的时候**引用行紧跟每个 `### ` 块**，不要留到最后统一补。
- 每追加 1-2 问就跑一次"问题数 vs 引用行数"。
- 一旦漏了，用 9.3 的结构化脚本补，**不要用文本锚点匹配**。

### 坑 2：并行 agent 在本机网关不可靠

派多个 Agent 并行写文件时，反复出现：

- `API Error: 502 请求转发失败`
- `Stream error: error decoding response body`
- `subagent_tokens: 0`，**文件根本没写出来**

**结论**：本项目实际采用的是**主 agent 顺序手写**。
如果公司环境 agent 更稳定，可以再试并行，但**每次并行后必须逐文件跑 10.1 校验**，不能相信 agent 的自我汇报。

### 坑 3：超长 bash 命令容易被拒

把"写 Python 脚本 + 执行脚本"塞进一条超长 `cat > ... << EOF ... python3 ...` 命令，多次被权限拒绝。

**改用**：Write 工具写脚本 → 单条简短 Bash 执行。稳定得多。

### 坑 4：heredoc 标记残留

追加后不检查，偶尔会在正文里留下 `PROBLEMS_END` 字样。

**防御**：追加后 `grep -n 'PROBLEMS_END' <file>`，有输出就删。

### 坑 5：全角/半角引号与破折号

文件里同时存在 `"…"`、`"…"`、`——→` 等。写脚本做匹配时极易失败。

**防御**：凡是批量改文件，**用结构定位（行号、标题前缀）而不是长文本锚点**。

### 坑 6：平台差异

| 操作 | macOS | Linux |
|------|-------|-------|
| sed 原地编辑 | `sed -i '' '$ d' f` | `sed -i '$ d' f` |

公司环境大概率是 Linux，注意改。

### 坑 7：README 与正文不同步

写完一卷忘了更新 README 的进度表，导致索引与实际不符。

**防御**：把"更新 README"写进提交前的固定清单。
